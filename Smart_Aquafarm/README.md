# WaterWise AI — ฉบับเชื่อมต่อครบวงจร

โปรเจกต์นี้เชื่อมสองส่วนที่แต่ก่อนแยกกันอยู่ (โมเดล AI พยากรณ์ภัยแล้ง กับหน้าเว็บ UI) เข้าด้วยกันจริง
ผ่าน backend เดียว ที่ดึง **ตำแหน่ง GPS จริง + พยากรณ์อากาศจริง (Open-Meteo, ฟรี ไม่ต้องใช้ API key)**
แล้วให้ผลวิเคราะห์ 3 ด้านตามโจทย์ "บริหารจัดการน้ำสำหรับเกษตรกร": **ปริมาณน้ำ, คุณภาพน้ำ, และแนวโน้มภัยพิบัติ (ภัยแล้ง + น้ำท่วม)**
พร้อม**บันทึกประวัติจริงลงฐานข้อมูล**ทุกครั้งที่ใช้งาน

```
WaterWise_AI_Complete/
  backend/
    app.py                      <- Flask server: รวม API + เสิร์ฟหน้าเว็บ
    waterwise_drought_rf.joblib <- โมเดลที่เทรนไว้แล้ว (ของเดิม)
    waterwise.db                <- ฐานข้อมูล SQLite (สร้างอัตโนมัติตอนรันครั้งแรก)
    requirements.txt
    training_report.json, feature_importance.csv, predict_example.py  <- ของเดิม เก็บไว้อ้างอิง
  frontend/
    index.html, style.css, app.js  <- หน้าเว็บ (อัปเดตให้ดึงข้อมูลจริงแล้ว มี 5 หน้า: หลัก/น้ำฝน/วิเคราะห์/ประวัติ/โปรไฟล์)
```

## วิธีรัน

```bash
cd backend
pip install -r requirements.txt
python app.py
```

แล้วเปิดเบราว์เซอร์ไปที่ **http://localhost:5000**
- เบราว์เซอร์จะขอสิทธิ์ตำแหน่ง (GPS) — กด "อนุญาต" เพื่อให้ระบบพยากรณ์ตามพิกัดจริงของคุณ
- ต้องมีอินเทอร์เน็ต เพราะระบบเรียก Open-Meteo (พยากรณ์อากาศ + ประวัติฝนย้อนหลัง) และ Nominatim/OpenStreetMap (แปลงพิกัดเป็นชื่อสถานที่)

## เชื่อมต่ออะไรแล้วบ้าง (ของจริงทั้งหมด ไม่ใช่ข้อมูลตัวอย่าง)

| ส่วน | มาจากไหน |
|---|---|
| ตำแหน่งผู้ใช้ | `navigator.geolocation` ของเบราว์เซอร์ |
| ชื่อสถานที่ที่แสดงผล | Nominatim/OpenStreetMap reverse geocoding |
| ปริมาณฝน/อุณหภูมิ 16 วันข้างหน้า | Open-Meteo Forecast API |
| จำนวนวันฝนไม่ตกติดต่อกัน | Open-Meteo Historical Archive API (30 วันย้อนหลัง) |
| ดัชนีความชื้นในดิน | Open-Meteo `soil_moisture_0_to_7cm` |
| **ความเสี่ยงภัยแล้ง** | โมเดล AI `waterwise_drought_rf.joblib` (RandomForest ที่เทรนไว้แล้ว) รันจริงทุกครั้ง |
| **คุณภาพน้ำ** | กฎเกณฑ์ทางอุทกวิทยา (rule-based) จากฝน/วันแล้งต่อเนื่อง/อุณหภูมิจริง — ไม่ใช่โมเดล AI หรือเซนเซอร์จริง (ดูหัวข้อด้านล่าง) |
| **ความเสี่ยงน้ำท่วม** | เกณฑ์ปริมาณฝนสะสม (rule-based) จากพยากรณ์ฝนจริง — ไม่ใช่โมเดล AI |
| **ประวัติ/บันทึกข้อมูล** | ฐานข้อมูล SQLite (`backend/waterwise.db`) บันทึกอัตโนมัติทุกครั้งที่เปิดแอป + บันทึกมือได้จากหน้า "ประวัติ" |
| ปริมาณน้ำที่เก็บได้ (ลิตร) | คำนวณจากฝนจริง × พื้นที่รับน้ำ × Runoff coefficient (0.85) |

### ทำไมคุณภาพน้ำ/น้ำท่วมถึงเป็น "กฎเกณฑ์" ไม่ใช่ "โมเดล AI"

ไฟล์โมเดลที่ให้มา (`waterwise_drought_rf.joblib`) ถูกเทรนมาเพื่อพยากรณ์ **ภัยแล้ง** เท่านั้น ไม่มีชุดข้อมูลหรือโมเดลสำหรับคุณภาพน้ำ (pH/สารปนเปื้อน) หรือน้ำท่วมมาด้วย และไม่มีเซนเซอร์ IoT จริงเชื่อมต่อ การจะ "เทรนโมเดล AI" คุณภาพน้ำขึ้นมาโดยไม่มีข้อมูลจริงมารองรับจะเป็นการสร้างตัวเลขที่ดูน่าเชื่อถือแต่ไม่มีความหมายจริง

แทนที่จะทำแบบนั้น ระบบใช้ **สูตรกฎเกณฑ์ที่โปร่งใส** ซึ่งเป็นหลักการที่ใช้กันทั่วไปในงานอุทกวิทยา:
- **คุณภาพน้ำ**: ฝนตกหนัก (>40มม.) ลดคะแนนจากความเสี่ยงตะกอน/น้ำขุ่น, วันแล้งต่อเนื่อง (>10 วัน) ลดคะแนนจากความเสี่ยงสาหร่าย/แบคทีเรียสะสมในน้ำนิ่ง, อุณหภูมิสูง (>32°C) ลดคะแนนจากการเติบโตของสาหร่าย → รวมเป็นคะแนน 0-100 และระดับ ดี/ปานกลาง/ต้องกรองก่อนใช้ (ดูฟังก์ชัน `estimate_water_quality` ใน `backend/app.py`)
- **น้ำท่วม**: ใช้เกณฑ์ปริมาณฝนสะสมทำนองเดียวกับเกณฑ์ฝนหนักที่กรมอุตุฯ ใช้ทั่วไป (`estimate_flood_risk`)

ทั้งสองส่วนนี้ **แสดงป้ายกำกับในแอปตลอดเวลาว่าเป็นการประเมินเบื้องต้นแบบกฎเกณฑ์ ไม่ใช่ AI** เพื่อไม่ให้สับสนกับผลพยากรณ์ภัยแล้งซึ่งเป็น AI จริง หากในอนาคตมีข้อมูลจากเซนเซอร์คุณภาพน้ำจริง ก็สามารถเทรนโมเดลจริงมาแทนสูตรนี้ได้

### ระบบบันทึก/ประวัติข้อมูล (ของใหม่)

ทุกครั้งที่แอปวิเคราะห์สถานการณ์น้ำ (ทั้งตอนเปิดแอปและตอนรีเฟรชตำแหน่ง) ระบบจะบันทึกข้อมูลของวันนั้นลงฐานข้อมูล SQLite โดยอัตโนมัติ (upsert ตามวันที่) ได้แก่ ปริมาณน้ำ/การใช้น้ำ ปริมาณฝน ลิตรที่เก็บได้ ผลภัยแล้ง คุณภาพน้ำ และความเสี่ยงน้ำท่วม — ดูย้อนหลังได้ที่หน้า **"ประวัติ"** ในแอป (กราฟแท่ง + รายการย้อนหลัง) และแก้ไขข้อมูลของวันนั้นด้วยตนเองได้ผ่านปุ่ม "บันทึกปริมาณน้ำวันนี้ด้วยตนเอง"

## สิ่งที่ยังเป็นการประมาณ/ต้องรู้ไว้ (บอกตรง ๆ)

1. **จังหวัด/ลุ่มน้ำ/รหัสสถานี** — ไฟล์ต้นฉบับไม่มีตารางพิกัดสถานีจริงมาด้วย มีแค่รายชื่อ 15 จังหวัด/8 ลุ่มน้ำ/45 รหัสสถานีที่โมเดลเคยเห็นตอนเทรน ระบบเลยจับคู่ตำแหน่ง GPS กับ "จังหวัดที่ใกล้ที่สุด" (ดูใน `backend/app.py` ตัวแปร `PROVINCES`) ซึ่งเป็นการประมาณ ไม่ใช่ข้อมูลสถานีจริง — อย่างไรก็ตาม โมเดลให้น้ำหนักฟีเจอร์ตัวเลข (ฝน/อุณหภูมิ/วันแล้งติดต่อกัน/ความชื้นดิน) รวมกันกว่า 80% จึงกระทบผลลัพธ์ไม่มาก
2. **แนวโน้มรายวันของ "วันฝนไม่ตกติดต่อกัน" และ "ความชื้นดิน" ในอนาคต** — ใช้สูตรจำลองอย่างง่าย (ไล่นับวันแล้งเพิ่ม/ลดความชื้นดินตามฝนพยากรณ์แต่ละวัน) ไม่ใช่โมเดลแยกต่างหาก เป็นวิธีที่โปร่งใสในการแปลงพยากรณ์ฝนให้เป็นแนวโน้มรายวัน
3. **พยากรณ์เกิน 16 วัน (เช่นแท็บ "1 เดือน")** — แหล่งข้อมูลฟรีที่ใช้ไม่รองรับ ระบบเลยแสดงข้อความแจ้งตรง ๆ แทนการสร้างตัวเลขลวง
4. **ความแม่นยำของโมเดล (99.9% ในรายงานเดิม)** — `training_report.json` ระบุไว้เองว่าตัวเลขนี้สูงผิดปกติเพราะ label ผูกกับฟีเจอร์ `consecutive_dry_days`/`soil_moisture_index` โดยตรง ระบบจึงแสดงคำเตือนนี้ในหน้าแอปทุกครั้ง (การประเมินนี้เหมาะเป็นแนวทางเบื้องต้น ไม่ควรใช้ตัดสินใจสำคัญโดยไม่ตรวจกับข้อมูลภาคสนามจริง)
5. **คุณภาพน้ำ และความเสี่ยงน้ำท่วม** — เป็นสูตรกฎเกณฑ์ (rule-based) ไม่ใช่โมเดล AI ที่เทรนจากข้อมูลจริง เพราะไม่มีชุดข้อมูล/เซนเซอร์จริงมาให้ (อธิบายละเอียดในหัวข้อด้านบน) แอปติดป้ายกำกับสิ่งนี้ไว้ตลอดเพื่อไม่ให้เข้าใจผิดว่าเป็นผลจาก AI

## ถ้าไม่ได้รันผ่าน backend (เช่น เปิดไฟล์ index.html ตรง ๆ)

หน้าเว็บจะตรวจพบว่าเรียก API ไม่ได้ และสลับเป็น **"โหมดสาธิต"** อัตโนมัติ พร้อมแบนเนอร์แจ้งเตือนสีเหลือง
เพื่อให้ยังกดดูหน้าตาแอปได้ แต่ตัวเลขทั้งหมดในโหมดนี้เป็นข้อมูลตัวอย่าง ไม่ใช่ค่าจริง (หน้า "ประวัติ" จะแจ้งว่ายังไม่มีประวัติให้ดูเช่นกัน เพราะต้องมี backend ถึงจะบันทึกได้)

## จะพัฒนาต่อ

- แทนที่ `PROVINCES` ด้วยตารางพิกัดสถานีจริง ถ้ามีข้อมูลต้นทางของหน่วยงานที่เก็บข้อมูลชุดนี้
- แทนสูตรคุณภาพน้ำ/น้ำท่วมด้วยโมเดล AI จริง หากมีชุดข้อมูลจากเซนเซอร์ IoT ภาคสนามมาเทรน
- ใช้บริการพยากรณ์ระยะยาวแบบมีค่าใช้จ่าย หากต้องการแนวโน้มเกิน 16 วัน
- ย้ายฐานข้อมูลจาก SQLite ไปเป็นระบบที่รองรับผู้ใช้หลายคนพร้อมกัน หากจะใช้งานจริงในวงกว้าง
